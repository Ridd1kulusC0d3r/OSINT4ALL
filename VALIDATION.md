# Validation Model / Modelo de Validação

OSINT4ALL is AI-assisted. Therefore **verification is part of the data model**, not a decorative disclaimer.

## Status

| Status | Meaning |
|---|---|
| 🟢 Verified | URL and main capability manually checked |
| 🟡 Needs review | Added from research/community/AI and awaiting current validation |
| 🟠 Changed | Tool exists but scope, pricing, ownership, URL or capability changed |
| 🔴 Broken/unsafe | Dead, compromised, misleading or unsuitable |
| ⚪ Historical | Preserved for historical or methodological value |

## Minimum validation checklist

- [ ] Canonical URL resolves.
- [ ] Project/service name matches the listed resource.
- [ ] Description reflects the current capability.
- [ ] Jurisdiction tag is correct.
- [ ] Access model is stated: free, freemium, paid, API key, account, local install.
- [ ] Source type is stated: official, academic, commercial, community, open-source.
- [ ] Last verification date is recorded.
- [ ] Security/reputation concerns are checked for downloadable tools.
- [ ] Privacy and legal caveats are recorded where relevant.
- [ ] Archived/replacement URL is noted if the source moved.

## Evidence confidence

For analytical workflows, do not confuse **tool confidence** with **finding confidence**.

Suggested scale:

- **A — Primary/official source**
- **B — Strong independent source**
- **C — Community or secondary source with corroboration**
- **D — Unverified claim / discovery lead**
- **E — Contradicted, obsolete or unreliable**

A tool can be verified and still return weak evidence. A source can be authoritative for one field and useless for another.

## AI-assisted additions

Any resource added primarily through AI-assisted curation should default to **🟡 Needs review** until a human confirms the URL and essential description.
